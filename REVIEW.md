CRITICAL -
1) Полное несоблюдение принципов SOLID и DDD:
Методы index и today обращаются сразу к слою, берущему непосредственный метод Laravel - это
в корне неверно, т.к. подобный ф-ционал должен лежать в слое DataProvider.
2) Грубейшее нарушение в методе today - на вход подается сущность Room, вместо стандартного request. Лучше передавать на вход тот же request, и вызывать сущность Bookings
метод list у Bookings. Либо же, если нам принципиален вход через Room, лучше создать RoomController и через него вызывать метод bookings().

MAJOR -
1) Все методы моожно было сделать более стандартными и универсальными для CRUD-приложения. Примеры
    
* index => list
* store => add/addWithResponse
* destroy => delete

А today вообще убрать, т.к. его ф-цию может исполнять метод getById с доп фильтром по полю starts_at

2) Получение ID пользователя из запроса - для безопасности можно брать из авторизованного пользователя;
3) Отсутствует строгая типизация возвращаемых результатов методов
4) Лучше использовать абстрацию, а не прямой SQL-запрос, т.к. по утверждениям вендора это безопаснее

MINOR -
Логгеры и респонсы можно вывести на отдельную абстракцию и вызывать эти методы 1 раз,
в зависимости от кодов статусов в соответствующих местах кода.
